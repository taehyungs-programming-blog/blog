## 사전지식 DXGI(DirectX Graphics Infrastructure)

**DXGI (DirectX Graphics Infrastructure)**는 DirectX 10부터 도입된 저수준 그래픽 인프라로, Direct3D와 하드웨어 사이의 공통 프레임워크를 제공

### 이게 왜 필요할까?

#### 근본적 이유

* DirectX 9까지는 D3D가 모든 걸 다 함. 디바이스 생성부터 화면 출력, 전체화면 전환까지 전부 D3D API 의 역할. 그런데... 이게 문제가 많았습니다 :<
* 중복 코드: D3D9, D3D10, D3D11... 각 버전마다 같은 기능(화면 출력, 모니터 열거 등)을 계속 다시 구현
* API 간 호환성 없음: D3D9과 D3D10을 같이 쓰려면 거의 불가능

#### 관심사의 분리

* DXGI: "하드웨어와 OS 레벨" - GPU 찾기, 모니터 관리, 화면 출력
* D3D: "렌더링 API" - 그래픽스 파이프라인, 셰이더, 리소스
* 이렇게 나누니까 각자 역할이 명확해지고 코드도 깔끔

### DXGI의 역할

- **하드웨어 추상화**: GPU, 모니터 등의 그래픽 하드웨어를 추상화하여 관리
- **플랫폼 독립성**: Direct3D 버전(D3D11, D3D12)과 무관하게 공통 인터페이스 제공
- **디스플레이 관리**: 전체화면/창모드 전환, 해상도 변경, 다중 모니터 지원
- **리소스 공유**: 여러 그래픽 API 간 리소스 공유 가능
- **버퍼 관리**: 스왑체인을 통한 버퍼링 및 화면 출력

### 주요 DXGI 인터페이스

#### IDXGIFactory

**역할**: DXGI를 사용하기 위해 필요한 각종 인터페이스 생성의 진입점

#### 주요 기능
- **IDXGIAdapter 열거**: 시스템에 설치된 그래픽 카드 목록 조회
- **IDXGISwapChain 생성**: 화면 출력을 위한 스왑체인 생성
- **전체화면 상태 관리**: 전체화면 전환 및 관리

## D3D12 주요 개념

- **Command List**: GPU에게 실행시킬 명령들을 기록하는 컨테이너
- **Command Allocator**: Command List가 명령을 기록할 메모리를 관리 ((주의) CPU에 메모리가 올라감)
- **Command Queue**: CPU에서 기록한 Command List를 GPU에 제출하여 실행
- **Fence**: CPU와 GPU 간의 동기화를 위한 객체

---

## Command List

### 개념

* Command List(`ID3D12GraphicsCommandList`)는 GPU가 실행할 그래픽 명령들을 기록하는 객체
* CPU에서 명령을 기록하고, Command Queue에 제출하면 GPU가 순차적으로 실행

### 특징

- **Recording State**: 생성 직후 또는 Reset 호출 후 명령을 기록할 수 있는 상태
- **Closed State**: Close 호출 후 Command Queue에 제출할 수 있는 상태
- **Command List Type**:
  - `D3D12_COMMAND_LIST_TYPE_DIRECT`: 그래픽 및 컴퓨트 명령 (가장 일반적)
  - `D3D12_COMMAND_LIST_TYPE_BUNDLE`: 미리 기록된 명령 번들 (재사용 가능)
  - `D3D12_COMMAND_LIST_TYPE_COMPUTE`: 컴퓨트 전용
  - `D3D12_COMMAND_LIST_TYPE_COPY`: 복사 전용

### 생성 방법

```cpp
ID3D12GraphicsCommandList* pCommandList = nullptr;
ID3D12CommandAllocator* pCommandAllocator = nullptr;

// 1. Command Allocator 생성
hr = pDevice->CreateCommandAllocator(
    D3D12_COMMAND_LIST_TYPE_DIRECT,
    IID_PPV_ARGS(&pCommandAllocator)
);

// 2. Command List 생성
hr = pDevice->CreateCommandList(
    0,                                  // nodeMask (멀티 GPU용)
    D3D12_COMMAND_LIST_TYPE_DIRECT,    // 타입
    pCommandAllocator,                  // 메모리 할당자
    nullptr,                            // 초기 Pipeline State (선택)
    IID_PPV_ARGS(&pCommandList)
);

// 3. Command List는 생성 시 Recording 상태이므로 Close 필요
pCommandList->Close();
```

### 주요 메서드

```cpp
// 명령 기록 시작 (Reset)
pCommandList->Reset(pCommandAllocator, pPipelineState);

// 리소스 상태 전환
pCommandList->ResourceBarrier(
    1,
    &CD3DX12_RESOURCE_BARRIER::Transition(
        pResource,
        D3D12_RESOURCE_STATE_PRESENT,
        D3D12_RESOURCE_STATE_RENDER_TARGET
    )
);

// 렌더 타겟 클리어
const float clearColor[] = { 0.0f, 0.0f, 1.0f, 1.0f };
pCommandList->ClearRenderTargetView(rtvHandle, clearColor, 0, nullptr);

// 드로우 콜
pCommandList->DrawInstanced(vertexCount, 1, 0, 0);

// 명령 기록 종료
pCommandList->Close();
```

## Command Allocator

### 개념

* Command Allocator(`ID3D12CommandAllocator`)는 Command List가 명령을 기록할 때 사용하는 메모리를 관리

### 특징

- **메모리 관리**: Command List의 명령들이 저장될 메모리 공간 제공
- **재사용 가능**: GPU가 명령 실행을 완료한 후 Reset 호출로 재사용
- **Command List와 1:N 관계**: 하나의 Allocator에 여러 Command List가 연결될 수 있음 (단, 동시에 Recording 중인 것은 하나만 가능)

### 생성 방법

```cpp
ID3D12CommandAllocator* pCommandAllocator = nullptr;

hr = pDevice->CreateCommandAllocator(
    D3D12_COMMAND_LIST_TYPE_DIRECT,
    IID_PPV_ARGS(&pCommandAllocator)
);
```

### Reset 규칙

```cpp
// GPU가 해당 Allocator의 명령을 모두 실행 완료한 후에만 Reset 가능
// Fence를 통해 GPU 실행 완료를 확인한 후 호출
pCommandAllocator->Reset();
```

**⚠️ 주의사항**: GPU가 아직 실행 중인 명령을 가진 Allocator를 Reset하면 **정의되지 않은 동작**이 발생

## Command Queue

### 개념

* Command Queue(`ID3D12CommandQueue`)는 Command List를 GPU에 제출하여 실행하는 큐
* CPU가 명령을 기록한 Command List를 이 큐에 넣으면, GPU가 순차적으로 꺼내서 실행

### 생성 방법

```cpp
ID3D12CommandQueue* pCommandQueue = nullptr;

D3D12_COMMAND_QUEUE_DESC queueDesc = {};
queueDesc.Type = D3D12_COMMAND_LIST_TYPE_DIRECT;
queueDesc.Priority = D3D12_COMMAND_QUEUE_PRIORITY_NORMAL;
queueDesc.Flags = D3D12_COMMAND_QUEUE_FLAG_NONE;
queueDesc.NodeMask = 0;

hr = pDevice->CreateCommandQueue(&queueDesc, IID_PPV_ARGS(&pCommandQueue));
```

### Command List 실행

```cpp
// Command List 배열 생성
ID3D12CommandList* ppCommandLists[] = { pCommandList };

// Command Queue에 제출하여 GPU 실행
pCommandQueue->ExecuteCommandLists(
    _countof(ppCommandLists),  // 개수
    ppCommandLists             // Command List 배열
);
```

### Signal을 통한 Fence 제어

```cpp
// Command Queue에 Fence Signal 명령 삽입
// Queue의 이 지점까지 명령이 실행되면 Fence 값을 업데이트
pCommandQueue->Signal(pFence, fenceValue);
```

## Fence

### 개념

* Fence(`ID3D12Fence`)는 CPU와 GPU 간의 동기화를 위한 객체
* GPU의 작업 진행 상태를 추적하고, CPU가 GPU의 작업 완료를 대기할 수 있게 함

### 동작 원리

```
CPU                         GPU
 │                           │
 ├─ CommandList 기록         │
 ├─ ExecuteCommandLists()    │
 ├─ Signal(fence, N)         │
 │                           ├─ CommandList 실행 시작
 ├─ GetCompletedValue()      │
 │   (아직 N보다 작음)        │
 │                           ├─ 명령 실행 중...
 │                           ├─ 명령 실행 완료
 │                           ├─ Fence 값을 N으로 설정
 ├─ GetCompletedValue()      │
 │   (N 이상, 완료!)          │
```

### 생성 방법

```cpp
ID3D12Fence* pFence = nullptr;
UINT64 fenceValue = 0;
HANDLE fenceEvent = nullptr;

// 1. Fence 생성
hr = pDevice->CreateFence(
    0,                          // 초기 값
    D3D12_FENCE_FLAG_NONE,     // 플래그
    IID_PPV_ARGS(&pFence)
);

// 2. 이벤트 핸들 생성 (CPU 대기용)
fenceEvent = CreateEvent(nullptr, FALSE, FALSE, nullptr);
```

### Fence를 통한 동기화

#### 방법 1: 폴링(Polling)

```cpp
// GPU에 Fence Signal 명령 제출
const UINT64 targetValue = ++fenceValue;
pCommandQueue->Signal(pFence, targetValue);

// CPU에서 GPU 완료 대기 (폴링 방식)
while (pFence->GetCompletedValue() < targetValue)
{
    // 대기 (비효율적 - CPU 사이클 낭비)
}
```

#### 방법 2: 이벤트 대기 (권장)

```cpp
// GPU에 Fence Signal 명령 제출
const UINT64 targetValue = ++fenceValue;
pCommandQueue->Signal(pFence, targetValue);

// GPU가 아직 완료하지 않았다면
if (pFence->GetCompletedValue() < targetValue)
{
    // Fence 값이 targetValue에 도달하면 이벤트 발생
    pFence->SetEventOnCompletion(targetValue, fenceEvent);
    
    // CPU를 Sleep 상태로 전환하여 대기 (효율적)
    WaitForSingleObject(fenceEvent, INFINITE);
}
```

### Fence 값 관리

```cpp
class Renderer
{
private:
    ID3D12Fence* m_pFence;
    UINT64 m_fenceValue;        // 현재 Fence 값
    HANDLE m_fenceEvent;

public:
    UINT64 SignalFence()
    {
        // Fence 값 증가 후 Signal
        m_fenceValue++;
        m_pCommandQueue->Signal(m_pFence, m_fenceValue);
        return m_fenceValue;
    }

    void WaitForFence(UINT64 targetValue)
    {
        // GPU가 해당 값에 도달할 때까지 대기
        if (m_pFence->GetCompletedValue() < targetValue)
        {
            m_pFence->SetEventOnCompletion(targetValue, m_fenceEvent);
            WaitForSingleObject(m_fenceEvent, INFINITE);
        }
    }

    void WaitForGPUIdle()
    {
        // 모든 GPU 작업 완료 대기
        UINT64 currentFence = SignalFence();
        WaitForFence(currentFence);
    }
};
```

```cpp
BOOL CD3D12Renderer::CreateDescriptorHeap()
{
	HRESULT hr = S_OK;

	// 렌더타겟용 디스크립터힙을 생성함으로서 메모리 할당
	D3D12_DESCRIPTOR_HEAP_DESC rtvHeapDesc = {};
	rtvHeapDesc.NumDescriptors = SWAP_CHAIN_FRAME_COUNT;	// SwapChain Buffer 0	| SwapChain Buffer 1
	rtvHeapDesc.Type = D3D12_DESCRIPTOR_HEAP_TYPE_RTV;
	rtvHeapDesc.Flags = D3D12_DESCRIPTOR_HEAP_FLAG_NONE;
	if (FAILED(m_pD3DDevice->CreateDescriptorHeap(&rtvHeapDesc, IID_PPV_ARGS(&m_pRTVHeap))))
	{
		__debugbreak();
	}

	m_rtvDescriptorSize = m_pD3DDevice->GetDescriptorHandleIncrementSize(D3D12_DESCRIPTOR_HEAP_TYPE_RTV);

	return TRUE;
}
```

```cpp
// RTV 디스크립터힙으로 부터 핸들을 받고
CD3DX12_CPU_DESCRIPTOR_HANDLE rtvHandle(m_pRTVHeap->GetCPUDescriptorHandleForHeapStart());

for (UINT n = 0; n < SWAP_CHAIN_FRAME_COUNT; n++)
{
    // m_pRenderTargets에 스왑체인의 주소를 담는다
    m_pSwapChain->GetBuffer(n, IID_PPV_ARGS(&m_pRenderTargets[n]));
    // m_pRenderTargets와 rtvHandle를 연결. 이제 rtvHandle에 쓰면 스왑체인에 써진다
    m_pD3DDevice->CreateRenderTargetView(m_pRenderTargets[n], nullptr, rtvHandle);
    // ++의 역할
    rtvHandle.Offset(1, m_rtvDescriptorSize);
}
```

```cpp
void CD3D12Renderer::BeginRender()
{
	//
	// 화면 클리어 및 이번 프레임 렌더링을 위한 자료구조 초기화
	//
	if (FAILED(m_pCommandAllocator->Reset()))
		__debugbreak();

	if (FAILED(m_pCommandList->Reset(m_pCommandAllocator, nullptr)))
		__debugbreak();

	CD3DX12_CPU_DESCRIPTOR_HANDLE rtvHandle(m_pRTVHeap->GetCPUDescriptorHandleForHeapStart(), m_uiRenderTargetIndex, m_rtvDescriptorSize);

	m_pCommandList->ResourceBarrier(1, 
        &CD3DX12_RESOURCE_BARRIER::Transition(m_pRenderTargets[m_uiRenderTargetIndex],  // 여기에
        D3D12_RESOURCE_STATE_PRESENT,                                                   // present를
        D3D12_RESOURCE_STATE_RENDER_TARGET));                                           // rt로

	// Record commands.
	const float BackColor[] = { 0.0f, 0.0f, 1.0f, 1.0f };
	m_pCommandList->ClearRenderTargetView(rtvHandle, BackColor, 0, nullptr);

}
```

## 동기화 흐름

### 프레임 렌더링 사이클

```
┌─────────────────────────────────────────────────────┐
│              Frame N 렌더링 사이클                    │
└─────────────────────────────────────────────────────┘

CPU                                     GPU
 │                                       │
 ├─ 1. CommandAllocator->Reset()        │ (Frame N-1 실행 중)
 │                                       │
 ├─ 2. CommandList->Reset(Allocator)    │
 │                                       │
 ├─ 3. CommandList에 명령 기록          │
 │    - ResourceBarrier                  │
 │    - ClearRenderTargetView            │
 │    - DrawInstanced                    │
 │    - ResourceBarrier                  │
 │                                       │
 ├─ 4. CommandList->Close()             │
 │                                       │
 ├─ 5. ExecuteCommandLists()            │
 │                                       ├─ Frame N 실행 시작
 ├─ 6. Present()                        │
 │                                       │
 ├─ 7. Signal(Fence, N)                 │
 │                                       ├─ 명령 실행 중...
 ├─ 8. WaitForFenceValue(N)             │
 │    (Frame N-1 완료 대기)              │
 │                                       ├─ Frame N 완료
 │                                       ├─ Fence = N
 ├─ 이벤트 발생, CPU 깨어남             │
 │                                       │
 ├─ 다음 프레임으로...                   │
 │                                       │
```

### 더블 버퍼링에서의 Fence 사용

```cpp
// 각 프레임마다 별도의 리소스 사용
const UINT FRAME_COUNT = 2;
ID3D12CommandAllocator* pCommandAllocators[FRAME_COUNT];
UINT64 frameFenceValues[FRAME_COUNT] = { 0, 0 };
UINT frameIndex = 0;

void Render()
{
    // 현재 프레임의 CommandAllocator가 GPU에서 사용 완료되었는지 확인
    if (pFence->GetCompletedValue() < frameFenceValues[frameIndex])
    {
        pFence->SetEventOnCompletion(frameFenceValues[frameIndex], fenceEvent);
        WaitForSingleObject(fenceEvent, INFINITE);
    }

    // GPU 사용 완료 확인 후 Reset
    pCommandAllocators[frameIndex]->Reset();
    pCommandList->Reset(pCommandAllocators[frameIndex], nullptr);

    // 렌더링 명령 기록
    RecordCommandList();
    pCommandList->Close();

    // GPU에 제출
    ExecuteCommandList();

    // Present
    pSwapChain->Present(1, 0);

    // 현재 프레임에 Fence 값 기록
    frameFenceValues[frameIndex] = ++currentFenceValue;
    pCommandQueue->Signal(pFence, frameFenceValues[frameIndex]);

    // 다음 프레임으로
    frameIndex = (frameIndex + 1) % FRAME_COUNT;
}
```
